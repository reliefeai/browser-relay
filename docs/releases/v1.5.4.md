# Browser Relay 1.5.4

Fix background scrolling unexpectedly bringing Chrome tabs and windows to the
foreground. Hidden tabs now scroll through the DOM, including nested scrollable
panels, without activation. Older callers passing `allowFocus:true` to scroll
also stay in the background. Foreground scrolling keeps native wheel input.

The Skill, runtime instructions and MCP tool descriptions now tell agents to
preserve the user's foreground tab by default. Explicit focus remains available
when the user requests foreground operation or a visual demonstration.

Hidden sites may defer rendering new content. Scroll results distinguish viewport
movement from observed text changes; an unchanged feed is not a reason to steal
focus. Background iframe scrolling requires an explicit target with `frameId`.

Regression coverage checks real tab visibility and Chrome activation events.
Live verification in the user's Chrome confirmed that background reads, input,
semantic clicks and scrolling leave the test tab hidden throughout.

## Upgrade

```bash
npm install -g @linsoai/browser-relay@1.5.4
browser-relay restart
browser-relay skill
browser-relay doctor
```

Reload the existing unpacked Browser Relay extension in Chrome to load the new
executor. Run the install command printed by `browser-relay skill` to refresh
installed Skills, and restart persistent MCP clients so agents receive the
updated foreground policy. The extension ZIP is attached to this release.
